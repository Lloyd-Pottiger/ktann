# Expose split targets before draining their source

A split first persists target identities, then uses a multi-transaction protocol in which one exposure transaction creates both targets, installs their incoming Child Entries, and marks the source Draining atomically, so no committed state holds a partially published split. Every step stays a small bounded transaction that can be retried independently. While the source is Splitting, foreground writes may continue changing it. Leaf training therefore reads all source entries and their Vector Records through one consistent snapshot, closes that transaction, and runs K-means without holding KV locks; target centroids are a routing model learned from that snapshot, not an authoritative description of later membership. Publishing targets does not validate a whole-partition epoch or restart merely because concurrent writes changed the source. After the source becomes Draining, inserts are redirected and migration reloads authoritative current membership.

The root remains Partition Key 1 and is promoted only after its entries move. This protocol accepts that target centroids may lag concurrent changes, along with searchable intermediate states and routing retries, to avoid long write transactions and bound split-versus-ingest conflicts; exact atomic movement rather than centroid freshness preserves membership correctness. Split training deliberately has no additional sampling, memory, or CPU bound: even an abnormally enlarged source trains from its complete snapshot, favoring centroid quality and one simple training rule at the cost of resource use proportional to source size.

Each new target is `ReceivingSplit { source }`: it is searchable, accepts redirected and migrated entries, and supports exact delete, but cannot itself split or merge. The exposure transaction's first successful commit fixes both target centroids forever: a competing attempt conflicts on the update-protected source authority pair and retries onto the persisted DrainingSplit state, so no worker ever overwrites a published centroid. Because exposure is atomic, a Splitting source with an already-installed target is a torn committed state and fails closed rather than being adopted. For a non-root source, the same transaction rediscovers the source's unique incoming Child Entry by an exact bounded root-down scan, update-protects the traversed parent Header and the source edge, and verifies that the parent still contains the source and accepts new children; failure abandons the step so a later traversal can rediscover the source's current parent. Root targets have no parent: they occupy the exclusive target slots persisted in Partition Key 1's Splitting state until the root exposes them. The update-protected source authority pair prevents orphans and prevents a stale worker from recreating or relinking a target after the source advances without retaining permanent partition tombstones.

The transition to Draining commits inside the exposure transaction, so the source never commits into a DrainingSplit behind incomplete targets. The transition does not rediscover or revalidate the targets' current parent references: installation established one exact incoming Child Entry per target, and adjacent-level maintenance may subsequently move each entry, even to different parents, without reading target state. The root has no parent and exposes its targets through its Draining state. This transition deliberately ignores source entries, count, and cache epoch so training and publication never restart or revalidate because of concurrent foreground writes; its source Header write can still conflict with a concurrent foreground write to the source, and the caller's whole-step retry absorbs that. A target becomes Ready only after its source has been fully drained.

Draining does not block foreground data changes. A new insert routes directly to the nearer target; an upsert whose Record Location still names the source atomically removes its source entry and inserts into the nearer target; and exact delete follows the current Record Location whether it names source or target. These mutations update-protect the relevant topology states and replay as a whole if those states change.

A leaf drain first obtains a bounded batch of Record IDs from a short read snapshot, then opens a write transaction and re-reads each source entry, Record Location, and Vector Record. An entry removed by a concurrent completed mutation is skipped; a remaining entry inconsistent with its record or location is corruption. The current Vector Record is normalized and rotated, then routed against the two persisted target centroids with a Partition Key tie-break; its unchanged absolute RaBitQ7 payload is copied rather than re-encoded. No durable cursor is stored: each batch starts at the source's current smallest entry because successful moves delete that prefix. Internal drains apply the same exact source-delete/target-insert rule to Child Entries but need neither Record Location nor Vector Record reads.

An internal split trains outside its read transaction from the complete consistent-snapshot set of full-f32 Child Entry centroids. During draining, it reloads each current Child Entry and routes that centroid against the two persisted target centroids, atomically moving the entry and both exact Header counts. It does not read the referenced child partition's state: child and parent maintenance are independent, and exact Child Entry ownership is the coordination point. Internal and leaf splits use the same state protocol and zero-count completion; internal partitions simply omit Record Location, Vector Record, and Synopsis work.

The exact update-protected Header count is the sole authority for source emptiness; completion does not repeat an entry scan. One short final transaction verifies the corresponding Draining state and zero count, promotes both targets from ReceivingSplit to Ready, and switches the topology. For a non-root it removes the source Child Entry and deletes the source State, Header, Synopsis, and centroid metadata; for the root it converts Partition Key 1 in place into a Ready internal root containing the two target Child Entries. Atomic entry moves and Header updates are the invariant, so a redundant empty-range check would add I/O and implementation complexity without strengthening the contract.
