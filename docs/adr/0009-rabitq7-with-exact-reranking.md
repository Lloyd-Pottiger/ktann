# Use RaBitQ7 leaves with exact reranking

Production leaves use an absolute per-vector RaBitQ7 algorithm rather than a partition-centroid-relative one-bit codec. After metric preprocessing and one persisted index-seeded Givens rotation, each dimension is encoded as one sign bit plus six magnitude bits. Each Leaf Entry stores its vector-local f32 least-squares scale, exact u32 squared integer-code norm, and an upward-rounded f32 reconstruction-error bound. Persisting the integer-code norm makes L2 metadata exactly consistent with the stored scale. No partition quantization parameters exist. Consequently an unchanged entry can copy its versioned RaBitQ7 payload verbatim during split or merge even when the target centroid differs; only insert and a vector-changing upsert re-run preprocessing, rotation, and encoding. KTANN owns and versions the complete codec, algorithm, and formulas and validates optimized kernels against its scalar oracle.

Approximate distance and a reconstruction-error bound form a `[lower, upper]` interval for every candidate. Inner product and cosine use query norm times reconstruction error; L2 derives its bound from estimated distance and reconstruction error. The scalar f64 implementation is the oracle, but production may use CPU-selected optimized f32 scalar or SIMD dot products. This improves the common search path at the deliberate cost of not promising bitwise-identical approximate candidate sets across hardware at floating-point interval or budget boundaries. Non-finite decoded or derived results are Corruption. Rough selection retains the bounded top set plus interval-overlap candidates before original f32 vectors are batch-read and reranked with f64 accumulation; exact rerank ordering within the selected candidates remains distance then RecordId.

The routing pipeline first validates the caller vector, applies cosine normalization when needed while leaving L2 and inner-product vectors unnormalized, and then applies the seeded rotation before RaBitQ7 encoding. Query routing uses the identical preprocessing and rotation. Exact rerank always uses the stored unrotated original vector: cosine recomputes norm/dot in f64, rejects zero vectors, and L2 returns Euclidean distance after squared-distance ranking, while inner product exposes distance as negative dot product. Any non-finite original or derived value is rejected rather than clamped.

The versioned per-entry payload has a fixed 12-byte little-endian header—`scale: f32`, `code_norm_squared: u32`, and `reconstruction_error_upper: f32`—followed by `ceil(dimension / 8)` sign bits and `ceil(6 * dimension / 8)` six-bit magnitude data. Manifest dimension determines the exact payload length, so entries do not repeat dimension or component lengths. Both streams are LSB-first; unused padding must be zero. Codec version also fixes the initial `max_abs / 63` scale, nearest rounding with halfway cases away from zero, positive sign for zero magnitude, the f64 least-squares rescale against fixed integer codes, and the canonical all-zero encoding. Inner-product intervals may be negative. L2 clamps only rough distance and its lower endpoint to zero and requires a finite upper endpoint. Cosine approximate and exact values are not clamped to their theoretical range, so unexpected numeric behavior stays observable rather than hidden.
