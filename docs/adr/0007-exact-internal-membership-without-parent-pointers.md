# Keep exact child membership without reverse parent pointers

Every ordinary non-root partition has exactly one Child Entry in one parent in every committed state, and structural moves atomically add the target reference and delete the source reference. The only alternate incoming topology reference is a root split's persisted target slot: its not-yet-published target is owned exclusively by Partition Key 1 until the root exposes it, and can never also have a parent Child Entry. Partitions do not persist reverse parent pointers: traversal and maintenance carry the observed parent, validate that reference while applying a change, and reroute after conflict; this preserves one authoritative incoming reference without the write amplification and coordination of a bidirectional graph.

Maintenance at adjacent levels may proceed concurrently. Moving a Child Entry can change its child's parent even while that child is itself splitting or merging; an operation carrying the former parent fails validation. When a non-root partition's incoming edge must be discovered without a carried parent, maintenance walks from the root down to the required parent level and point-reads `(parent, child)` ChildEntry keys across that level's bodies rather than relying on approximate centroid routing or scanning sibling Child Entries. It requires one incoming edge and update-protects that edge in the transition transaction; conflict repeats discovery, while sibling parents remain uncontended. This keeps foreground ChildEntry moves free of a reverse-pointer write at the cost of bounded O(parent-level partitions) discovery work. A child's intermediate state therefore does not lock its parent against maintenance.
