# Keep exact child membership without reverse parent pointers

Every ordinary non-root partition has exactly one Child Entry in one parent in every committed state, and structural moves atomically add the target reference and delete the source reference. The only alternate incoming topology reference is a root split's persisted target slot: its not-yet-published target is owned exclusively by Partition Key 1 until the root exposes it, and can never also have a parent Child Entry. Partitions do not persist reverse parent pointers: traversal and maintenance carry the observed parent, validate that reference while applying a change, and reroute after conflict; this preserves one authoritative incoming reference without the write amplification and coordination of a bidirectional graph.

Maintenance at adjacent levels may proceed concurrently. Moving a Child Entry can change its child's parent even while that child is itself splitting or merging; an operation carrying the former parent fails validation. When an empty split/merge source must be removed, maintenance performs an exact bounded root-down scan of every Child Entry at the required parent level and matches PartitionKey, rather than relying on approximate centroid routing. It requires one incoming edge and update-protects that edge in the completion transaction; conflict repeats discovery. This keeps foreground ChildEntry moves free of a reverse-pointer write at the cost of rare O(parent-level entries) completion work. A child's intermediate state therefore does not lock its parent against maintenance.
