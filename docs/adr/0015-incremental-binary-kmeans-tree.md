# Grow an incremental binary K-means tree from an empty root

Each tree is created atomically by its first foreground upsert, is immediately searchable, and grows only through deterministic balanced k=2 splits with immutable non-root centroids; concurrent first inserts race through unique creation, and an empty root and its allocator remain until Logical Index drop. A split initializes its two clusters with a deterministic farthest-pair choice: the entry farthest from the source centroid, then the entry farthest from that first seed, with distance ties ordered by Child or Record ID. Each Lloyd round orders entries by their distance difference to the two centroids and assigns exactly `floor(n/2)` entries to the left cluster, with ID tie-breaking; centroids use f64 accumulation and must convert to finite f32. Assignment stability stops training early, otherwise training stops after ten rounds. Leaf training reads original Vector Records and applies the metric's routing normalization and persisted rotation, while internal training uses the full-f32 centroids in Child Entries; an absent source Vector Record is corruption and leaves the searchable source intact for later diagnosis or retry. A Splitting source accepts foreground writes (see the expose-then-drain protocol) and can legally shrink below two entries before exposure, so training emits degenerate centroids for an undersized source — the single entry replicated, or the zero vector when empty — letting the split always advance; target centroids are routing models, not authority.

Partition sizing and split/merge triggers use exact entry counts rather than bytes or learned statistics, roots never collapse, and no separate bulk-build generation exists. These choices give up randomized initialization, unconstrained nearest-centroid clusters, bulk-trained topology, and adaptive fanout for reproducible balanced partitions and one uniform online mutation path. Every split trains from its complete consistent-snapshot source rather than sampling, so training resource use is intentionally proportional to the source's actual size.

Drain placement normally follows the two persisted centroids. Exact remaining and target counts reserve the last entries needed for each target to reach the configured minimum when possible, crediting entries already redirected into the targets. This viability bound prevents duplicate-heavy drains from immediately merging a small target back into its oversized source without replacing the learned distance-based assignment or persisting per-entry assignments; new foreground inserts still use ordinary nearest-centroid routing.

The caller configures only minimum and maximum partition entry counts. Validation requires minimum at least one, maximum at least two, and checked `2 * minimum <= maximum`; otherwise a newly balanced split could immediately put both targets below the merge threshold and create stable structural oscillation. Binary fanout, ten Lloyd rounds, and the split algorithm are fixed v1 protocol choices rather than public tuning knobs.
