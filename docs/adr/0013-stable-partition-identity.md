# Allocate stable partition identities in per-tree ranges

Each tree retains root Partition Key 1, never reuses a non-root key, and allocates non-root keys from transactionally reserved ranges of a per-Tree-Key high-water mark. Each Runtime keeps only a concurrent process-local `(Logical Index ID, Tree Key) -> [next, end)` cursor and reserves 1,024 keys when exhausted; it never persists the local next value. A crash safely loses the unused suffix. If reservation commit outcome is unknown, that entire candidate range is abandoned and a later attempt reserves after the latest persisted high-water rather than infer ownership under concurrent reservations. A locally issued ID is likewise never returned or reused if target creation fails or has unknown outcome, preventing stale workers from colliding with a replacement partition.

Reservation uses checked u64 arithmetic. Near exhaustion it may reserve the final nonzero suffix shorter than 1,024; once no legal ID remains, both Partition Key and namespace Logical Index ID allocation return the stable IdExhausted error. This trades dense identifiers for low contention, recovery without reservation tokens, and simple permanent uniqueness.
