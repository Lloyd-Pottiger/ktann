# Coordinate import admission with contention and Fixup backlog

Import Session batches use the ordinary atomic Foreground Mutation path while competing with Structure Maintenance for topology and leaf keys. Partition count is not a capacity signal: one batch may touch several leaves, many partitions may still share one hot Tree Key, and maintenance may conflict even when the local queue is nearly empty. Each session therefore starts with one active batch, treats its configured maximum as a ceiling, increases only under saturated clean demand, and contracts before a contended batch retries. A paused retry retains accepted-batch capacity and precedes new submissions; retry backoff does not occupy an active slot.

Import Admission also gates new batches on the process-local Fixup Backlog. The backlog watermark bounds how far foreground import may run ahead of pending and running maintenance; it is neither a durable convergence barrier nor an estimate of partition count. The default allows one Fixup to coexist with import and pauses new admission before a second joins the backlog. This avoids both unchecked maintenance debt and the fully serial oscillation produced when every single Fixup closes the gate. The numeric default remains an empirically validated operating point, not a persistent-format invariant.

Import never splits a caller batch to manufacture parallelism. Batch size remains a caller choice governed by atomicity, transaction limits, latency, and retry cost. Likewise, `max_partition_entries` configures the Split Threshold rather than a synchronous Foreground Mutation limit: a threshold-crossing partition remains searchable while bounded split work converges it. Queue saturation, worker loss, and process restart may delay convergence but must not compromise exact membership or searchability. A strict instantaneous partition-size bound would require synchronous admission or reserved capacity and is not part of this design.

An import optimization is incomplete if it proves only throughput or fewer retries. Representative validation must account for accepted records and batch failures, retry and mutation work, CPU and wall time, Fixup convergence, partition occupancy and over-threshold age, immediate and stable cold/warm recall, Search Budget truncation, and search latency. Process-local backlog alone cannot prove convergence because dropped or undiscovered Fixups are absent from it. A search-budget increase does not repair an admission policy that degrades topology quality; it merely transfers cost to reads. Fixed concurrency, concurrency derived from partition count, and an unqualified strict-zero-maintenance gate are rejected because none observes the whole write/maintenance/search system.
