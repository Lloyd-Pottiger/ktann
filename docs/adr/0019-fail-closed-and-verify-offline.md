# Fail closed and verify invariants outside hot paths

Normal reads and writes trust atomically maintained projections and do not add Record Location or cross-projection reads merely to prove consistency, but any corruption naturally encountered fails the operation with structured index/tree/partition/record context rather than being skipped or repaired. KTANN v1 provides a bounded read-only verifier over exactly one consistent backend snapshot to audit encoding, reachability, unique child and leaf membership, exact counts, Record–Location–Leaf relationships, and synopsis conservatism concurrently with foreground work. It never joins pages from different snapshots: transaction expiry, deadline, or cancellation returns an error rather than an advisory cross-snapshot report. Consequently a live FoundationDB database may not support complete verification of a large index; operators must use an offline copy or backend snapshot when the audit cannot finish inside its snapshot lifetime.

VerifyOptions contains deadline/cancellation plus independent issue, object, and memory limits: defaults are 100 issues, 1,000,000 decoded logical objects, and 64 MiB, with hard caps of 10,000, 100,000,000, and 1 GiB respectively. Reaching any limit stops the audit and returns `complete=false`; ordered merge scans minimize resident state and all buffers/sets/sort runs count toward memory. There is no continuation, persistent spill, sampling, or repair mode. Each structured issue identifies its kind plus Logical Index ID, Tree Key hash, Partition Key, and optional Record ID, but never includes raw Tree Keys, vectors, payloads, or filter values. The verifier deliberately provides no automatic or in-place repair because choosing authority under exact membership is unsafe.
