# Use a Tree-Key-sharded K-means forest

A Logical Index is divided into disjoint K-means trees by an immutable ordered subset of non-NULL filter fields; each record belongs to exactly one Tree Key rather than being replicated across recall trees. The ordered Tree Key field list may be empty, meaning the Logical Index has one tree; a non-empty list has no repeated fields, requires each selected schema field to be non-nullable, and treats order as part of the persistent configuration. Equality and finite-set constraints route directly, while predicates that do not determine complete Tree Keys enumerate existing roots under an independent hard scanned-key dimension of the global Search Budget; the longest equality/IN prefix forms ordered scan ranges and remaining constraints filter decoded keys exactly. Enumeration completes before fair tree-local traversal, and exhaustion searches only the deterministically enumerated prefix while reporting that bias. This preserves data locality and supports broad queries without an arbitrary tree-count limit or unbounded forest scans.
