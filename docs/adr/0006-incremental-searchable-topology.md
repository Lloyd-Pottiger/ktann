# Maintain topology through searchable incremental states

KTANN grows from an empty searchable root and performs split and merge as bounded, idempotent transactions whose every committed intermediate state remains searchable; it has no bulk-build generation, durable work queue, global maintenance owner, or lease. One process-wide bounded in-memory queue serves all indexes, deduplicates split/merge by index, tree, and partition, and drops overflow without blocking foreground work; workers retire after bounded retry exhaustion because later access can rediscover durable work. Foreground batches coalesce discoveries by partition and offer only committed Headers that can advance: threshold-crossing Ready partitions and durable split/merge sources. Healthy Ready partitions and ReceivingSplit targets are not admitted because they have no independent state-machine step. A Ready partition crossing a soft threshold is admitted immediately, but access only re-admits an intermediate state after its persisted state-start time exceeds a configurable stalled timeout; only real state transitions refresh that time, and future or backward-clock observations are treated as not stalled. The timestamp permits conservative cooperation rather than ownership or correctness, avoiding the lock-conflict storm caused by every bulk-ingest access trying to assist a fixup that is already progressing. An optional process-local Import Session admits ordinary atomic batches in bounded waves, returns a Batch Token for each accepted batch, and pauses admission when that index's known fixup backlog is high. Finish returns every accepted batch result in submission order without publishing a durable Ready state or claiming cluster-wide convergence.

Runtime construction is synchronous but requires a current Tokio multi-thread runtime, validates all process configuration, and immediately starts maintenance workers; an absent or incompatible runtime is InvalidArgument rather than a deferred first-use failure. Runtime and Index clones share one RuntimeInner, while workers retain only Weak references so they cannot keep the process resource alive after its final user handle. Explicit async shutdown is idempotent: it stops new admission, cancels queued maintenance, waits for admitted foreground completion guards and already-running short maintenance transactions, then awaits the backend's native-resource shutdown hook before releasing it; it does not wait for topology convergence. An admitted operation retains its real result; RuntimeClosed applies only to later calls. Durable intermediate states remain searchable for a later Runtime.

An ImportSession is a non-cloneable process-local scheduler bound to one Index and creates no persistent state. Its mutable submit method waits for bounded capacity, accepts one caller-sized ordinary atomic mutation batch, and returns a process-local Batch Token; accepted batches may execute concurrently. Admission pauses while any Structure Maintenance is pending or running. A session starts with one active batch, learns useful concurrency from saturated clean work and retryable contention, and never exceeds the configured `min(available_parallelism, 4)` default ceiling. Finish closes admission, waits for every accepted batch, and returns each token's result in submission order, but makes no cross-process or full-index convergence claim. Dropping without finish cancels work not yet admitted to commit; a committing batch remains owned by the Runtime completion guard and finishes without a session observer. ImportOptions adds no second batch-size or structural cadence controls.

Searchability of intermediate topology follows exact incoming references rather than recursive split-family expansion. A non-root Splitting or Draining source and each installed ReceivingSplit target participate independently through their current parent Child Entries, even if adjacent-level maintenance moved them to different parents. ReceivingSplit searches like any partition at its level but cannot start maintenance; Merging likewise searches normally and has no enumerable target family. Adding a source's targets again would duplicate traversal and distort budgets.

Root split is the sole exception because its targets temporarily have no parent. While root is Splitting, search reads only its source body because targets are empty and unexposed. While root is Draining, the same-level frontier explicitly includes Partition Key 1 and both persisted targets, with each distinct body consuming visited-partition budget. Exact atomic moves ensure a record belongs to only one of those bodies. Within a query, `{Tree Key, Partition Key}` suppresses duplicate physical body reads and budget charges, but discovering the same non-root child through two different parent Child Entries is Corruption rather than a silently deduplicated topology.

The durable state machine has exactly five variants: Ready, `Splitting { left, right }`, `ReceivingSplit { source }`, `DrainingSplit { left, right }`, and Merging. Final detach, target promotion, and root level addition occur in the already-required short atomic completion transactions, so no Deleting, AddingLevel, Staging, tombstone, owner, lease, or cursor state is persisted. State stores only its variant and associated Partition Keys, codec version, and Unix-epoch nanosecond `state_started_at`; only a genuine variant transition refreshes the timestamp, an invalid persisted timestamp is Corruption, and a future value is conservatively not stalled.

Time is a core-internal injectable Clock seam, not a KV Backend capability. Production uses system wall time only to encode persisted state-start timestamps and Tokio monotonic time for deadlines and retry backoff; deterministic tests inject a fake clock. If current wall time cannot be represented as valid Unix nanoseconds, the transition fails before writing rather than storing zero or clamping. Stalled detection uses checked `now - started >= timeout`, treats `now < started` as not stalled, and is evaluated only after the process-local dedupe table shows no identical fixup pending or running. Timeout must be positive and representable; its default is checked `max(1ms, 1s * max_partition_entries / 128)`, and invalid derived configuration is rejected rather than enabling immediate assistance.

Header separately stores one-based u32 level, exact count, and cache epoch. Leaves are level one, every internal Child Entry descends exactly one checked level, only root promotion increases root level, and a non-root partition's level is immutable. Search batch-reads State, Header, and Synopsis in one snapshot when needed. Mutation and maintenance update-protect only the State/Header values that decide whether their writes are legal; ordinary reads do not lock metadata merely to restate invariants. Missing required values or an incompatible level, body kind, or state combination is Corruption.
