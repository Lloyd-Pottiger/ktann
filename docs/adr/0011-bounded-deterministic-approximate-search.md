# Expose bounded approximate search

Search uses level-scaled beam traversal and one hard budget over scanned Tree Keys, visited partitions, visited Leaf Entries, and exact-rerank candidates; the requested k is only an upper bound. Traversal and tie-breaking are deterministic within one snapshot, codec, and selected numeric kernel, while CPU-selected f32/SIMD RaBitQ accumulation may change interval-boundary candidates across hardware. Budget exhaustion returns accumulated hits plus usage and exhaustion details, while deadline or cancellation is an error; hits contain only Record IDs and exact distances, deliberately avoiding fill guarantees, implicit payload reads, and cross-call snapshot sessions.

RaBitQ candidate retention is bounded in two stages. For a leaf with n eligible entries, `r=min(n,max(2*k,64))`; it retains the rough top r, adds interval-overlap entries whose lower bound does not exceed that leaf's r-th upper bound, and caps this intermediate set at `min(4*r, remaining request rerank budget)`, truncating by lower bound, estimated distance, then Record ID. The merged candidates use the global kth-smallest upper bound, or positive infinity when fewer than k candidates exist, are sorted by estimated distance and Record ID, truncated to remaining rerank budget, and only then batch-read for exact distance. Checked arithmetic rejects overflow. SearchOutcome reports `rabitq_overlap_truncated=true` if any leaf cap discarded a qualifying overlap; this makes the recall/resource trade-off visible while preventing wide error intervals from growing memory to the visited-entry limit.

The owned SearchRequest contains query vector, `k` in `1..=65,536`, optional typed Predicate, and request SearchOptions. Optional nonzero budget overrides use Runtime defaults when absent and return InvalidArgument rather than clamp when above the fixed runtime hard caps. Effective exact-rerank budget must be at least k; when omitted checked arithmetic computes `min(max(4*k,100),65,536)`. SearchOutcome is a non-exhaustive structure containing hits, typed usage counters, one exhaustion boolean per budget dimension, and the overlap-truncation flag.

Usage measures logical algorithm work, not backend RPC shape: Tree Keys actually decoded and checked from the directory; distinct `{Tree Key, Partition Key}` bodies logically visited, including cache hits; Leaf Entries read and considered under the exact predicate, including entries whose evaluation is skipped because the Synopsis proves AllMatch; and Vector Records actually read and exactly reranked. A dimension is exhausted only if eligible pending work is prevented by its depleted budget, not merely because natural completion lands exactly on the limit. Several dimensions may be exhausted together. Search stops starting work that consumes each exhausted dimension, finishes already-materialized permissible work, and returns deterministically ordered exact-distance/Record-ID hits.
