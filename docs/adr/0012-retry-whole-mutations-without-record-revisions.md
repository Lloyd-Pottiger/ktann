# Retry whole mutations without record revisions

KTANN uses last-write-wins full-record replacement and no caller-visible or stored per-record revision. A mutation routes without locks, then a typed storage operation update-protects and validates authoritative keys before atomically applying all record and index changes. Batch apply performs an all-or-nothing validation pass before producing mutations; within the same live transaction it may retain unaffected route decisions, clear stale transaction-local loads, reroute only rejected records, and then revalidate the whole batch. A backend abort discards all routes and replays the complete operation in a fresh transaction, using capped exponential backoff with jitter for at most eight attempts by default; the configurable attempt count is at least one, and exhaustion returns ContentionExhausted. An unknown commit outcome never enters this loop and is returned without retry to avoid an older request overwriting a later successful write.

Insert-if-absent has a stable RecordAlreadyExists error distinct from InvalidArgument and contention. An unknown insert outcome is not recovered merely by observing that its ID now exists, since another writer may own that record; the caller may read and compare the complete authoritative Record. Empty batch-get and batch-mutate operations succeed with empty outputs. Batch-get preserves order and duplicate IDs, while a non-empty atomic mutation batch rejects duplicate IDs. Every record API requires the caller's opaque Record ID to contain `1..=256` raw bytes; its memcomparable expansion is separately checked against the Backend key limit.

An atomic batch returns its ordered, input-length outcomes only after all validation and commit succeed. Any item failure returns one Error for the entire operation, with the input position and Record ID in structured context, and never a partial outcome vector. Stable ErrorKind is the matching contract; Error may additionally carry backend, operation, Logical Index ID, Tree Key hash, Partition Key, and Record ID without rendering sensitive raw Tree Keys, field values, vectors, or payloads in its default Display. Backend errors remain chained sources without a stable concrete source type.
