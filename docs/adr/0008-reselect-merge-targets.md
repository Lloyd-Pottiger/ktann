# Reselect merge targets through same-level routing

A merge begins only from a non-root Ready partition whose exact Header count is below the configured minimum and after ordinary same-level routing establishes at least one other Ready target; roots never merge or collapse, and an intermediate-state partition cannot start another merge. The operation durably marks only its source as Merging. That source remains searchable and supports exact delete, but no new insert enters it; an upsert whose Record Location still names the source must atomically relocate to a Ready same-level target. If no such target remains after bounded retries, the foreground operation returns ContentionExhausted rather than making the source grow again.

Each maintenance batch uses ordinary same-level centroid routing to obtain ordered candidates, skips the source and every non-Ready partition, and chooses the nearest current Ready target. Its write transaction update-protects and revalidates that state; a conflict discards the route and starts target selection again, with no durable or process-local target affinity. Targets may therefore vary and may cross the split threshold, possibly causing a later split.

Draining uses the split protocol's two-phase batch pattern. A short snapshot reads the source's current lowest-key entry batch, then a write transaction re-reads authority and skips entries already removed by a completed concurrent mutation. Leaf movement re-reads Record Location and Vector Record, uses the current normalized/rotated vector for routing, copies the unchanged absolute RaBitQ7 payload, and atomically moves the Leaf Entry, Location, exact Header counts, and target Synopsis expansion; the source Synopsis does not shrink. Internal movement routes the current full-f32 Child Entry centroid and atomically transfers that entry and both counts without reading child state. A remaining inconsistent projection is corruption.

If routing finds no Ready target, the source remains a searchable Merging partition and the fixup retires; a later relevant access may recover it after the stalled timeout. It never reverts to Ready and never manufactures an empty target. Exact count zero is sufficient to begin completion and no entry rescan is required. With transactional range clear, one short transaction validates the source state and observed parent Child Entry, removes that entry, and clears the complete source prefix. Without that capability, bounded point deletion retains and revalidates the terminal Merging State/Header until an empty cleanup page permits the final incoming-edge and metadata removal. No target state changes and no tombstone remains. A stale parent observation fails validation so later traversal can recover with the current parent.
